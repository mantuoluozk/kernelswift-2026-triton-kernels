# 燧原 S60 环境与迁移指南

本指南记录十个 KernelSwift Triton 算子从海光 BW1000、沐曦 C500 和 Ascend 910B 迁移到燧原 S60 的实际差异。

## 软件栈与设备接口

| 平台 | 监控命令 | PyTorch 设备 | 可见设备变量 | Triton 后端 |
| --- | --- | --- | --- | --- |
| 海光 BW1000 | `hy-smi` | `cuda`/HIP | `HIP_VISIBLE_DEVICES` | ROCm Triton |
| 沐曦 C500 | `mx-smi` | CUDA 兼容接口 | `MACA_VISIBLE_DEVICES` | mcTriton 3.0 |
| Ascend 910B | `npu-smi info` | `npu` | `ASCEND_RT_VISIBLE_DEVICES` | Triton-Ascend 3.2.1 |
| 燧原 S60 | `efsmi` | `gcu` | `TOPS_VISIBLE_DEVICES` | Triton 3.6 + triton_gcu |

S60 上应显式创建 `device="gcu"` 的张量，并用 `torch.gcu.synchronize()` 做计时同步。`torch_gcu` 会安装部分 CUDA API 迁移补丁，但不要据此假定所有 `device="cuda"` 字面量都能直接工作。

## 常用命令

```bash
# 设备状态、显存、利用率、温度和进程
efsmi
watch -n 1 efsmi

# 软件版本
python -m pip show torch torch-gcu triton triton-gcu

# Python 侧设备检查
python - <<'PY'
import torch
import torch_gcu
print("available:", torch.gcu.is_available())
print("count:", torch.gcu.device_count())
print("name:", torch.gcu.get_device_name(0))
print("allocated:", torch.gcu.memory_allocated(0))
print("reserved:", torch.gcu.memory_reserved(0))
PY

# 只暴露第 0 张逻辑卡
TOPS_VISIBLE_DEVICES=0 python program.py
```

`TOPS_VISIBLE_DEVICES` 不应在 Python 已初始化 GCU 后修改，否则设备枚举可能进入错误状态。

## 最小编译链验证

```bash
python platforms/enflame_s60/smoke_test.py
```

看到 `PASS Triton-GCU vector add` 才说明 PyTorch、torch_gcu、Triton JIT、triton_gcu 和设备执行链均已打通。只检查 `import triton` 不足以证明 kernel 能编译运行。

## 从海光迁移时最重要的差异

1. S60 的后端 warp 配置不能照搬海光。Task03 把 `num_warps` 从 1 改为 4 后由约 0.29 ms 退化到约 3.88 ms；Task06 最终采用 32 行 tile 和 1 warp。
2. 二维 grid 的每个维度存在后端限制。Task04 原方案的 `grid.y=477` 无法启动，改为把 segment 与 vocab block 展平成一维 program id。
3. 大向量 program 和大量 program 的成本都需要实测。Task07 的 2048 元素粗粒度版本比拆成 256 元素更快，但仍明显慢于厂商 `einsum`。
4. 某些整数表达式不是等价性能问题，而是稳定性问题。Task10 的 `offsets & 3` 在当前后端触发段错误，改为 `offsets % 4` 后稳定通过。
5. 宽 `tl.sum` 和 FP32 atomic 路径在 Task10 实测不稳定。最终由 Triton 融合 sigmoid 反向点算子，末级小归约交给 torch_gcu，既保留关键融合也避免崩溃。

## GELU 与整数类型警告

当前 torch_gcu 默认 GELU 使用 tanh 近似，并提示可通过 `ENFLAME_PT_GELU_ERF_ENABLE=true` 启用 erf。评测时应保持参考实现和优化实现处在同一环境设置，不要只改变其中一侧。

S60 还可能提示 Long/UInt64 被替换为 Int/UInt32。固定比赛形状不会溢出时不影响本次正确性，但通用实现需要重新检查索引上界和随机数状态。

## 推荐迁移顺序

1. 用 `efsmi` 确认设备健康和空闲。
2. 记录驱动、torch_gcu、Triton 与 triton_gcu 版本，不覆盖预装厂商栈。
3. 运行 smoke test，确认真实 JIT 与执行。
4. 用 `warmup=1/repeat=3` 逐题建立正确性基线。
5. 遇到段错误先缩小 tile，并替换位运算、宽归约和 atomic 等可疑路径。
6. 调参时一次只改变 tile 或 `num_warps`，用短测筛选。
7. 最后固定代码，以 `warmup=200/repeat=500` 完整回归并记录未加速项。

正式结果见 [S60 平台 README](README.md)。
