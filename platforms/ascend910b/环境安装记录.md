# Ascend 910B 环境安装记录

本文记录本项目在 Ascend 910B 实例上实际采用的环境搭建过程。目标是区分平台已经提供的底层软件和项目自行安装的 Python 包，使后续迁移到同类实例时能够复现，而不把服务器地址、账号、密码或实例编号写入仓库。

## 1. 最终环境

| 项目 | 实测值 | 来源 |
| --- | --- | --- |
| 操作系统 | openEuler 24.03 LTS-SP2 | 在线实例预装 |
| CPU 架构 | aarch64 | 在线实例 |
| NPU | Ascend 910B1，容器内 1 张逻辑卡 | 在线实例映射 |
| CANN Toolkit | 9.0.0，`V100R001C10SPC001B250` | 在线实例预装 |

| PyTorch | 2.10.0+cpu | 在线实例预装 |
| torch_npu | 2.10.0 | 在线实例预装 |
| Triton-Ascend | 3.2.1 | 项目虚拟环境安装 |

这里的 PyTorch 包名带有 `+cpu` 不代表只能使用 CPU。Ascend 设备后端由配套的 `torch_npu` 注册，实际设备通过 `torch.npu` 使用。

## 2. 哪些前提不能由 pip 代替

本次在线资源本身已经处于预配置容器中，并提供以下内容：

- Ascend 驱动和容器设备映射；
- CANN 9.0.0 Toolkit 与算子库；
- Python 3.11.15；
- 与 CANN 配套的 PyTorch 和 torch_npu；
- `npu-smi` 设备管理工具。

因此项目没有创建嵌套 Docker 容器，也没有自建镜像名。`install_env.sh` 只负责检查这些前提、创建 Python 虚拟环境并安装 Triton-Ascend，不能在一台裸机上替代驱动、固件、CANN 和 torch_npu 的安装。

## 3. 安装前检查

先确认操作系统、架构和设备：

```bash
cat /etc/os-release
uname -m
npu-smi info
python3 --version
```

确认 CANN 的实际版本：

```bash
cat /usr/local/Ascend/ascend-toolkit/latest/aarch64-linux/ascend_toolkit_install.info
```

确认 PyTorch、torch_npu 和 NPU 可用性：

```bash
python3 - <<'PY'
import torch
import torch_npu

print("torch:", torch.__version__)
print("torch_npu:", torch_npu.__version__)
print("npu available:", torch.npu.is_available())
print("device count:", torch.npu.device_count())
print("current device:", torch.npu.current_device())
print("device name:", torch.npu.get_device_name())
PY
```

只有 `torch.npu.is_available()` 为 `True` 时才继续。物理卡编号与容器内逻辑编号可能不同；本项目代码使用容器内的 `npu:0`。

## 4. 为什么固定 Triton-Ascend 3.2.1

Triton-Ascend 必须和 CANN 版本配套。本机是 CANN 9.0.0，因此固定 `triton-ascend==3.2.1`，不直接追随最新版本。更换 CANN 或 torch_npu 后，应重新核对官方版本关系并完成全部正确性回归。

参考资料：[Triton-Ascend 官方仓库](https://github.com/triton-lang/triton-ascend)、[Triton-Ascend 3.2.1 发布页](https://github.com/triton-lang/triton-ascend/releases/tag/v3.2.1)。

## 5. 实际安装命令

仓库脚本执行的核心命令如下：

```bash
cd /data/kernelswift-2026-triton-kernels

# 加载 CANN 环境。不同镜像可能提供其中一个路径。
if [[ -f /usr/local/Ascend/cann/set_env.sh ]]; then
    source /usr/local/Ascend/cann/set_env.sh
else
    source /usr/local/Ascend/ascend-toolkit/set_env.sh
fi

mkdir -p /data/venvs
python3 -m venv --system-site-packages \
    /data/venvs/kernelswift-ascend910b

/data/venvs/kernelswift-ascend910b/bin/python -m pip install \
    --disable-pip-version-check \
    'triton-ascend==3.2.1' \
    --extra-index-url=https://mirrors.huaweicloud.com/ascend/repos/pypi
```

实际使用时直接运行等价且带前置检查的脚本：

```bash
bash platforms/ascend910b/install_env.sh
```

使用 `--system-site-packages` 的原因是复用实例预装且已与 CANN 配套的 torch_npu。若使用完全隔离的普通 venv，虚拟环境中将看不到系统的 torch_npu；若在系统 Python 中直接升级 torch 或 torch_npu，又可能破坏厂商已经验证的软件组合。

## 6. 每次登录后的环境配置

每个新 Shell 都执行：

```bash
cd /data/kernelswift-2026-triton-kernels
source platforms/ascend910b/setup_env.sh
```

`setup_env.sh` 完成三件事：

1. 加载 CANN 的 `set_env.sh`，补齐编译器、算子库、`PYTHONPATH` 和 `LD_LIBRARY_PATH`；
2. 把 `/data/venvs/kernelswift-ascend910b/bin` 放到 `PATH` 最前面；
3. 设置 `PYTHONNOUSERSITE=1`，避免用户目录中的包污染已固定的环境。

确认当前解释器和关键包来自预期位置：

```bash
command -v python
python -m pip show triton-ascend torch torch-npu
```

预期 Triton-Ascend 位于虚拟环境，torch 和 torch_npu 位于系统 Python 的 site-packages。安装包版本是 `triton_ascend 3.2.1`；部分构建的 `import triton; print(triton.__version__)` 可能显示其上游 Triton 基线版本，判断安装版本时以 `pip show triton-ascend` 为准。

## 7. 编译链验证

仅成功导入 Python 包还不够，必须真正编译并执行一个 Triton kernel：

```bash
python platforms/ascend910b/smoke_test.py
```

预期输出：

```text
PASS Triton-Ascend vector add
```

然后进行最短的全题回归：

```bash
WARMUP=1 REPEAT=3 \
bash platforms/ascend910b/run_all_benchmarks.sh
```

全部通过后再使用正式参数：

```bash
WARMUP=200 REPEAT=500 \
bash platforms/ascend910b/run_all_benchmarks.sh
```

## 8. 从同类新实例复现

```bash
git clone <repository-url> /data/kernelswift-2026-triton-kernels
cd /data/kernelswift-2026-triton-kernels

npu-smi info
bash platforms/ascend910b/install_env.sh

python platforms/ascend910b/smoke_test.py
WARMUP=1 REPEAT=3 bash platforms/ascend910b/run_all_benchmarks.sh
```

复现成立的前提是新实例也提供兼容的 Ascend 驱动、CANN 9.0.0、Python 3.11、PyTorch 2.10 和 torch_npu 2.10。若底层版本不同，应把它视为一次新的平台迁移，不能直接沿用本记录中的固定版本。

## 9. 常见问题

### `ModuleNotFoundError: torch_npu`

通常是创建 venv 时漏掉 `--system-site-packages`，或者实例本身没有预装 torch_npu。先用系统 `python3` 验证，再重新创建虚拟环境。

### 找不到 CANN 动态库或编译工具

先执行 `source platforms/ascend910b/setup_env.sh`。如果仍失败，检查实例中的 CANN 安装路径是否与脚本探测的两个标准路径一致。

### `torch.npu.is_available()` 为 `False`

这属于驱动、设备映射或实例资源问题，不是安装 Triton-Ascend 可以解决的问题。先用 `npu-smi info` 检查设备状态。

### 第一次运行很慢

首次执行包含 Triton 编译、Ascend 后端代码生成和缓存写入，不能把它计入 kernel 性能。正式评测必须先 warmup，再统计多次运行的中位数。
