# 00：先建立算子优化的整体认识

## 1. 什么是算子

深度学习模型最终会分解为大量张量运算，例如加法、矩阵乘、Softmax、LayerNorm 和 Attention。框架中的一次 Python 调用不一定对应一个设备 kernel；一个看似简单的表达式也可能展开成多个 kernel 和多个中间张量。

例如：

```python
y = torch.log1p(torch.relu(x))
```

从数学上看只是两步逐元素计算，但实现可能经历 ReLU 输出写入显存、再次读回、执行 `log1p`、再写回。自定义 Triton kernel 可以把两步合并，让每个元素只读一次、写一次。

## 2. 为什么 PyTorch 已经很快，仍然值得写 Triton

PyTorch 的通用算子需要覆盖不同形状、布局、数据类型和硬件。比赛给出的形状往往固定，而且多个相邻算子可以一起考虑，因此有三类额外机会：

1. **融合**：减少 kernel launch 和中间张量读写；
2. **专用化**：利用固定维度展开循环、消除动态分支；
3. **数学变换**：利用单调性、公共因子抵消或重新排序，直接计算最终结果。

Task08 是最典型的 launch-bound 案例：PyTorch 用许多小 kernel 完成 20 轮行列归一化；Triton 把 4×4 矩阵放在片上状态中一次完成。Task04 则是内存与计算融合案例：不再物化 `[83, 30522]` 的完整 logits。

## 3. Triton 与 CUDA/HIP 的思维差异

CUDA/HIP 通常让程序员显式考虑“一个线程做什么”。Triton 更常用的思路是“一个 program 实例负责一个数据块”。program 内部通过块张量表达一组并行元素：

```python
pid = tl.program_id(0)
offsets = pid * BLOCK + tl.arange(0, BLOCK)
x = tl.load(x_ptr + offsets, mask=offsets < n)
```

这里 `offsets` 不是 Python 列表，也不是一个标量，而是编译器理解的向量/块张量。Triton 编译器负责把块张量映射到后端线程和指令。

在 BW1000 的 HIP 后端上，硬件执行单元以 wavefront 组织，DTK 26.04 手册说明一个 wavefront 包含 64 个线程。Triton API 仍使用参数名 `num_warps`；把它理解为“一个 program 分配多少并行执行资源”更稳妥，不要机械套用 NVIDIA 32 线程 warp 的细节。

## 4. 一个算子的四层视图

每次优化都应依次建立以下四层视图。

### 4.1 语义层

回答：算子数学上计算什么，输出必须满足什么？

例如 Task01：先按组取最大分数，选 4 个组，再从组内候选专家选 8 个，并对 8 个权重归一化。

### 4.2 形状与布局层

回答：每个维度代表什么，哪一维连续，stride 是多少？

行主序二维张量 `X[M, N]` 的地址通常是：

```text
address(X[i, j]) = X_ptr + i * N + j
```

Task07 把 `(batch, token)` 合并成 `row`，于是 `x[row, hidden]` 和四路 residual 都可以用连续 hidden 偏移访问。

### 4.3 执行层

回答：启动多少个 program，每个 program 计算哪个 tile，循环在哪个维度发生？

例如 Task06 的 grid 为：

```text
(ceil_div(83, 64), batch * heads) = (2, 16)
```

每个 program 负责 64 个 query 和一个 batch/head，K/V 按 32 个 token 流式扫描。

### 4.4 性能层

回答：时间主要花在 launch、显存、计算还是同步？

- 小张量、多步骤：常见 launch-bound；
- 逐元素、大张量：常见 memory-bound；
- 大型 GEMM：常见 compute-bound；
- 大型临时张量：可能同时受内存容量和带宽限制。

## 5. 建议的学习顺序

不要一上来写 Attention。推荐顺序：

1. Task05：学习扁平索引、mask 和融合；
2. Task08：学习 `tl.sum`/`tl.max` 和片上迭代；
3. Task07：学习数据复用、手工展开和多输出；
4. Task01：学习 Top-k、单调性与稳定归一化；
5. Task10：学习反向公式和多路归约；
6. Task02/04：学习 `tl.dot`、分块 GEMM 与跨算子融合；
7. Task03/06：最后学习在线 Softmax Attention；
8. Task09：补齐随机算子的语义一致性。

## 6. 每次动手都遵循的闭环

```text
确认接口和形状
  → 跑通 reference
  → 写公式和中间张量表
  → 测 reference 基线
  → 提出一个可验证的瓶颈假设
  → 写最小 Triton 版本
  → 先校验正确性
  → 再测性能
  → 扫参数并记录
  → 回归全部样例
```

如果一个修改无法说明它减少了什么（launch、字节、计算量、分支或同步），通常就不值得先做。
